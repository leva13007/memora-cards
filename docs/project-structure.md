# 📁 Project Structure

This document provides a **practical guide** to the file and folder structure of the Memora Cards project. It explains **where things are located** and **what naming conventions to use**.

> 📚 **Note**: For information about **why** the project is structured this way and the **architectural principles** behind it, see [`docs/memora-architecture.md`](./memora-architecture.md).

---

## Root Directory

```
memora_project/
├── docs/              # Documentation files
├── public/            # Static assets and default card files
├── src/               # Source code
├── dist/              # Build output (generated)
├── node_modules/      # Dependencies (generated)
├── .husky/            # Git hooks
├── eslint.config.js   # ESLint configuration
├── eslint.rules.js    # Custom ESLint rules
├── vite.config.ts     # Vite build configuration
├── tsconfig.json      # TypeScript configuration
├── package.json       # Project metadata and dependencies
└── pnpm-lock.yaml     # Dependency lock file
```

---

## Source Directory (`src/`)

The source code follows Feature-Sliced Design architecture. Here's the directory structure:

```
src/
├── app/               # Application entry point (routing, providers)
├── pages/             # Route-level page components
├── widgets/           # Complex UI blocks combining features/entities
├── features/          # User-facing features
├── entities/          # Domain models (card, deck, etc.)
└── shared/            # Shared utilities and components
    ├── ui/            # Atomic UI components (atoms → molecules → organisms)
    ├── lib/           # Utility functions
    ├── config/        # Constants and configuration
    └── types/         # Shared TypeScript types
```

> 💡 For detailed explanations of **what goes where** and **why**, including architectural principles and folder responsibilities, see [`docs/memora-architecture.md`](./memora-architecture.md).

## File Naming Conventions

- **Components**: PascalCase (e.g., `CardRow.tsx`)
- **Utilities**: camelCase (e.g., `parseCsv.ts`)
- **Tests**: Same name as file + `.test.ts` (e.g., `parseCsv.test.ts`)
- **Styles**: Component name + `.module.css` (e.g., `CardRow.module.css`)
- **Types**: camelCase (e.g., `cardTypes.ts`)

---

## Import Paths

Use relative imports within the same feature/entity, and absolute imports for shared code:

```typescript
// Within same feature
import { EditCardForm } from './ui/EditCardForm';

// From shared
import { Button } from '@/shared/ui/atoms/Button';
import { parseCsv } from '@/shared/lib/csv';
```

## Build Output

The `dist/` directory contains the production build:

```
dist/
├── index.html         # Entry HTML file
└── assets/           # Compiled JavaScript and CSS
    └── index-[hash].js
```

This directory is generated by running `pnpm build` and should not be committed to version control.
